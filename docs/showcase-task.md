# Showcase 任务设计：地图自动模式 vs 纯 GUI 模型

目标：设计一个任务，让「有地图的自动模式」在**步数 / token / 时长**三个维度上都明显优于
「纯 GUI（看截图逐步决策）」的模型。任务只读取，不修改任何状态。

---

## 一、主推任务

> **「帮我看三个设置：① 这台手机的电池容量是多少 mAh？② 境外漫游时允不允许用数据网络？
> ③ 『极速扫码』现在是开着还是关着？三个都要，一次说完。」**

### 标准答案（来自现有地图，逐字可核）

| 问题 | 答案 | 来源屏 |
|---|---|---|
| ① 电池容量 | **8550mAh(typ)** | `设置 → 我的设备` |
| ② 漫游是否允许数据 | **漫游时允许数据网络**（该开关存在，状态需现场读） | `设置 → 移动网络 → 漫游设置` |
| ③ 极速扫码 | **已关闭** | `设置 → 锁屏 → 注视感知 → 主动视觉感知` |

### 为什么这个任务对地图有利

三个答案分布在**三个不同的分支**，而且**深度不同**：

```
① 设置 → 我的设备                                  1 跳（行在首屏）
② 设置 → 移动网络 → 漫游设置                        2 跳（"漫游设置"在移动网络页下方）
③ 设置 → 锁屏 → 注视感知 → 主动视觉感知              3 跳（两处都在折叠线以下）
```

- 行名都很普通（锁屏 / 移动网络），**目标行在折叠线以下**，必须先滚动才能看到
- ③ 的目标藏在「注视感知」这个**看起来像开关、其实是入口**的行里
- 三处互不相关 → GUI 模型每换一个分支都要**重新定位**，无法复用上一跳的上下文

我们这边：`route` 一步到达每一屏（宏内部连点，不需要模型思考），模型只读答案。

## 二、预期差距（可测）

### 步数

| | 自动模式（有地图） | 纯 GUI 模型 |
|---|---|---|
| ① | `route 我的设备` + 读 | 1 次点击 + 读 |
| ② | `route 移动网络_漫游设置` + 读 | 点移动网络 + 滚动 + 点漫游设置 + 读（约 3-4 步） |
| ③ | `route 锁屏_注视感知` + 读 | 点锁屏 + 滚动 + 注视感知 + 主动视觉感知 + 读（约 5-6 步） |
| **合计** | **约 6-8 步** | **约 12-20 步** |

地图里 `移动网络_漫游设置` 的宏是 **4 步**、`锁屏_注视感知` 是 **5 步**——对我们是一个
"route" 动作，对 GUI 模型是 4-5 次"截图 + 决策"往返。

### Token

- GUI 模型每一步都要一张整屏截图（1280×2772 缩图约 1–1.5k token）+ 决策文本
- 12-20 步 ≈ **15–25k token**
- 自动模式：系统提示 + 地图操作段 + 2-3 张截图 ≈ **6–8k token**
- **差距约 2–3 倍**，而且 GUI 模型的步数越多差距越大

### 时长

- 自动模式的 `route` 重放是**纯点击**（每步约 1.5 秒，无模型往返）
- GUI 模型每步都有一次 VLM 往返（本机实测 2–5 秒）
- **预计快 2–4 倍**

## 三、测量协议（保证公平、可复现）

1. **同一台手机、同一份屏幕内容**，两个模式各跑一次，顺序对调再各跑一次（消除缓存效应）
2. 记录三项：
   - `steps`：App 里显示的步数（我们的任务详情页有）
   - `tokens`：usage 页面的 token 总数（我们已统计）
   - `wall time`：从提交到出答案的秒数
3. **答案必须逐字比对**（8550mAh / 已关闭），答错的一方该轮不计分
4. 说明环境：DeepSeek flash、同一份系统提示、同一台 Redmi K90

> 建议做成一张三行表：`步数 / token / 秒`，两列：`纯 GUI` vs `PhoneGo（地图）`。

## 四、备选任务

### B. 跨 App（展示通用性）

> **「微博的任务中心里，我现在连签几天、微博积分是多少？然后再看小红书的『我』页面上我的粉丝数。」**

- 地图里：`设置…` 不参与；微博 `任务收益/微博积分/已连签1天` 在一屏；小红书 `我` 是一屏
- GUI 模型的痛点：**换 App 后所有定位重置**，且两个 App 的入口位置完全不同
- 注意：粉丝数是会变的，建议只比"读到的数字"，不比绝对值

### C. 最短、最稳（用于开场演示"一步到位"）

> **「我的设备里的认证编号是多少？」**

- 答案：`56134791Y4ANY9C20XNY5`（`设置 → 我的设备 → 认证信息`，宏 6 步）
- 优点：答案唯一、不会变、只需一屏
- 缺点：只有一跳，差距不够震撼，适合做**开场**而不是主菜

## 五、风险与规避

| 风险 | 说明 | 规避 |
|---|---|---|
| **设置搜索框捷径** | 设置顶部有「搜索系统设置项」，GUI 模型理论上可以搜「极速扫码」 | 演示时说明：搜索结果常常是设置**项**而不是**页面**，且 ③ 需要打开开关所在页读状态；若担心，改用备选 B（无搜索） |
| 内容漂移 | 微博/小红书的内容每次都不一样 | 主推任务只用设置，值稳定 |
| 账号状态 | ①②③ 都是只读，不触发任何写入 | 已确认：三个目标页均无提交动作 |
| 屏幕尺寸差异 | 演示机与观众机不同不影响，宏按坐标+文本重定位 | 无需处理 |

## 六、一句话版本（讲给观众听）

> 「GUI 模型要一层层点进去找，每点一次都要看一眼截图；我们的地图里这条路已经录好了，
> 它直接照着走——三处藏在三层的设置，六步读完。」
